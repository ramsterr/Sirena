## Real Objective

You are building a pure Python library that implements spectrum-based fault localization using the Ochiai coefficient. Think of it like a statistical detective — given a set of "passing" and "failing" test cases (normal and anomalous traces), it computes which component (service) is most strongly associated with the failures. This library has no dependencies on Kubernetes, Jaeger, or Prometheus — it works on any data where you can classify executions as "pass" or "fail" and track which components were involved in each execution.

## Tool Objective

By the end of this project, the library must:
1. Accept a list of executions, each with a list of involved components and a pass/fail label
2. Compute the Ochiai score for each component
3. Return a ranked list of components by suspiciousness
4. Support multiple spectrum scoring formulas (Ochiai, Tarantula, Jaccard, DStar)
5. Be installable via pip with a clean API
6. Include comprehensive tests with known inputs and expected outputs

## What You Must Understand Before Coding

### Concept 1: The Ochiai Coefficient

The Ochiai coefficient for a component `s` is:

`Ochiai(s) = n_ef / sqrt(n_f * n_e)`

Where:
- `n_ef` = number of failing executions that contain component `s`
- `n_f` = total number of failing executions
- `n_e` = total number of executions (passing + failing) that contain component `s`

**Interpretation:**
- Score ≈ 1.0: component appears in almost all failing executions and few passing ones → very likely the cause
- Score ≈ 0.0: component appears in few failing executions or many passing ones → unlikely the cause

**Walk-through with numbers:**
100 executions total. 20 failing, 80 passing.

Component `inventory-service` appears in 19 failing and 5 passing:
`Ochiai = 19 / sqrt(20 * 24) = 19 / 21.9 = 0.868`

Component `frontend` appears in 20 failing and 80 passing (it's in every execution):
`Ochiai = 20 / sqrt(20 * 100) = 20 / 44.7 = 0.447`

The frontend has a lower score because it appears in ALL executions, so its presence doesn't distinguish failing from passing.

**Self-check:** 50 failing, 100 passing. Component X appears in 45 failing and 10 passing. Component Y appears in 50 failing and 100 passing. Which has a higher Ochiai score? Answer: X = 45/sqrt(50*55) = 45/52.4 = 0.859. Y = 50/sqrt(50*150) = 50/86.6 = 0.577. X is higher.

Formulas to implement:
- **Ochiai:** `n_ef / sqrt(n_f * n_e)`
- **Tarantula:** `(n_ef / n_f) / (n_ef / n_f + n_ep / n_p)` where `n_ep` = passing executions containing component, `n_p` = total passing
- **Jaccard:** `n_ef / (n_f + n_ep)`
- **DStar:** `n_ef^2 / (n_ep + n_nf)` where `n_nf` = failing executions NOT containing component

**How to verify it works:**
- Test with the example from Concept 1. inventory-service should score 0.868, frontend should score 0.447.
- Test with a known case: one component appears only in failing executions. It should score 1.0.
- Test with a component that appears in all executions. It should score < 0.5.

### Component 4.2: CLI Interface

**Purpose:** Run spectrum scoring from the command line.

**Input format (JSON):**
```json
{
  "executions": [
    {"components": ["frontend", "cart-service", "database"], "is_failing": true},
    {"components": ["frontend", "cart-service"], "is_failing": false},
    ...
  ]
}
```

**CLI commands:**
```bash
# Score from a JSON file
spectrum-score score --input executions.json

# Choose formula
spectrum-score score --input executions.json --formula tarantula

# Output as CSV
spectrum-score score --input executions.json --output csv
```

## Understanding Checkpoints

1. "Can I compute the Ochiai score by hand for a small set of 5 executions?" — If no, you don't understand the formula.
2. "Can I explain why Ochiai outperforms Tarantula when the frontend is in every execution?" — If no, re-read the walk-through in Concept 1.
3. "Do all four formulas produce correct results for known test cases?" — If no, check your counting logic for n_ef, n_f, n_e, etc.

## Common Mistakes

1. **Not handling division by zero.** If `n_f = 0` (no failing executions), Ochiai is undefined. Return 0 for all components. If `n_e = 0` (component never appeared), return 0.
2. **Confusing n_ef with n_ep.** `n_ef` = failing executions containing the component. `n_ep` = passing executions containing the component. These are different counts.
3. **Not normalizing Tarantula correctly.** Tarantula's denominator can be 0 if a component appears in no executions. Handle this edge case.
